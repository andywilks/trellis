# Documentation Rules

## Every Document Must Have
- A title as an H1 heading
- A date and status (Draft / In Review / Approved) in the header
- A clear statement of audience

## Formatting
- Use Mermaid for all diagrams — no external image links
- Use tables for structured comparisons
- Use code blocks with language identifiers for all code samples
- Headings: H1 for title, H2 for major sections, H3 for subsections — no deeper

## Traceability
- Every requirements document must reference the epic it belongs to
- Every design document must reference the requirements it addresses
- Every test document must reference the user stories it covers

## Prohibited
- Internal jargon without explanation
- TODO items without a linked issue
- Outdated information — update or delete it
